# Malka: Interview Reference

## Standard questions (Phase 1)

Ask until every answer below is known. Never assume; never dispatch while one is missing.

1. **Goal** — what is the high-level objective?
2. **Inputs** — what data or artifacts exist, and where?
3. **Output** — what should be produced, and where should it land?
4. **New or existing** — fresh work, or modifying/extending something?
5. **Constraints** — specific methods, formulas, priors, naming, deadlines?

These five are deliberately generic — they identify *which* domain skill governs the task and *what it needs to know*. They are not a substitute for that skill's own interview. Once the domain skill is identified (Phase 2 of `SKILL.md`), its own interview file goes deeper on domain-specific questions (e.g. `bayesian-regression/workflow/VALIDATION.md` asks about formula structure; `project-scaffolding/SKILL.md`'s Interview step asks clone-vs-new and model name).

## Trivial-request shortcut

For genuinely trivial requests — a fact, a file pointer, a one-line clarification — answer directly. No pipeline, no dispatch. Reserve the full interview + gate + dispatch flow for requests that will write or modify a lab work product.

## Signs the interview isn't done yet

- You are about to guess a formula, prior, exclusion cutoff, or folder name instead of asking.
- The user's answer to "output" is vague enough that the executor would have to invent a path.
- You don't yet know which domain skill applies — ask rather than routing on a guess.
