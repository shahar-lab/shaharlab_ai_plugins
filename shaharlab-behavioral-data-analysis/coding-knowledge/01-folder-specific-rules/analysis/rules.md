# The `analysis/` folder

`analysis/` holds empirical analyses — every job whose input is real data from
`data/processed/`.

## How many folders the work is

Count by what the folder produces, rather than by the word the request used for it:

| The folder produces | How many folders |
|---|---|
| fitted model objects (`brm()`, `stan()`, any saved fit) | **one folder per fit** |
| plots, tables, descriptive/summary statistics, data checks | **one folder for the coherent set** |

One formula applied to several filtered subsets of the data is **several fits, therefore several
folders** — not one folder. Sharing a formula shape does not make them one model; each subset
produces its own posterior, its own diagnostics, and its own saved artifact.

Descriptive work stays whole: a folder of five plot scripts producing five figures is one folder,
because it holds no fitted object and no diagnostics to separate.

```text
analysis/
└── [analysis_name]/
    ├── code/           short R scripts, numbered in main.R's order (01_prep_data.R, 02_fit_model.R, 03_plot_posteriors.R …)
    ├── artifacts/      machine-readable derived files (fitted .rds, saved data frames)
    ├── output/         human-facing results (plots, figures, tables)
    ├── main.R          the orchestrator — sources code/ scripts in order
    └── summary.md      the notebook — formula, hypotheses, variables, findings
```

## What each part is for

| Part | Rule |
|---|---|
| `code/` | Each script does one step and is sourced by `main.R`. Keep scripts to roughly 50–80 lines; split a longer one into two named steps. Names describe the step behind a two-digit prefix giving its position in `main.R`'s order, per `project-rules.md` §2.II — and inserting a step renumbers the ones after it in the same edit. |
| `artifacts/` | Anything a later script reads back: `brm()` fits, prepared data frames. Regenerated by rerunning `main.R`. |
| `output/` | Anything a human reads: plots (PDF + PNG), tables, reports. |
| `main.R` | Libraries, `rm(list = ls())`, the path block, then one `source()` per step. Reading it top to bottom is the full account of the analysis. |
| `summary.md` | Model name and formula, date, hypotheses, variables, and findings — filled in once the model is fitted. |

## The `main.R` path block

`template_main.R` beside this file carries the block, already written for this folder type — inject it
and set the folder name. `project-rules.md` §4 states the contract it satisfies and what each variable
holds.

Scripts in `code/` use those variables and define no paths of their own. Libraries and
`rm(list = ls())` live only in `main.R`.

## How the folder is handled

- Read input data from `data/processed/` by path; the folder keeps its own copy of nothing.
- Write only inside this folder — `artifacts/` for machine-readable, `output/` for human-facing.
- A figure in this folder is built from the `04-visualization` knowledge for its plot type rather than from raw ggplot. Where the card routed no plot-type file for a figure the specification asks for, take one as an `ADDED READ`.
- Model definitions live in `models/`; this folder fits and evaluates them.
- **One fitted model per folder.** If the specification handed to you contains more than one model
  fit, return `BLOCKED` and say how many you counted, rather than building them together in this
  folder. Descriptive folders (plots, tables, summary statistics) are exempt — they hold a coherent
  set.

## Building one

Create `code/`, `artifacts/`, `output/`; inject `template_main.R` as `main.R`; then replace
`<folder_name>` with the real name, and set the headers to the user's model name and formula.
To copy an existing analysis, use
`../../02-scaffolding/references/smart_clone.md`.

`summary.md` is written by Malka from the approved specification, not by the Writer building the
folder. Scaffold the three directories and `main.R`; the notebook arrives separately, shaped by
`template_summary.md` in this same subfolder.
